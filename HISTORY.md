- **Комментарий из корзины стирался при сохранении заказа** (~20 мин). Причина: `OrderBeforeSaved` (обработчик `OnSaleOrderBeforeSaved` в `include/orderHandlers.php`) при каждом `$order->save()` безусловно копировал значение order-свойства `COMMENT` в `USER_DESCRIPTION` — новый чекаут это свойство не заполняет (комментарий пишется в `USER_DESCRIPTION` напрямую в `CheckoutService::submit()`), поэтому оно пустое и стирало уже записанный комментарий прямо во время save(), до того как уведомление в бот/Б24 перечитывало заказ. Подтверждено temp-трассировкой: значение на месте перед save(), пропадает в уведомлении. Исправлено — свойство `COMMENT` перезаписывает `USER_DESCRIPTION` только если в нём реально есть текст.
- **Профиль не сохранял имя/фамилию/email из оформленного заказа** (~15 мин). В `OrderBeforeSaved` (`orderHandlers.php`) была попытка это делать, но она читала `$propsData['NAME']` ДО того, как этот массив вообще заполнялся (объявлялся ниже по функции) — условие всегда было ложным, сам автор оставил комментарий "$propsData is underfined", но не исправил. Плюс EMAIL не обрабатывался вовсе, а имя/фамилия ожидались одной строкой через пробел, хотя чекаут шлёт их отдельными свойствами NAME/SURNAME. Перенёс логику после заполнения $propsData, поля обновляются только если реально пустые в профиле.
- **Регистрация по SMS/Т-Банку заводила дубликаты аккаунтов** (~20 мин). Телефоны на сайте хранятся в LOGIN/PERSONAL_PHONE/PERSONAL_MOBILE в формате "79022031446" (11 цифр, без "+"), а `SmsAuthService`/`TBankAuthService` использовали сырое значение от клиента ("+79022031446" — фронтенд шлёт номер с плюсом) и для поиска, и для регистрации. Существующие аккаунты не находились, вместо этого заводился новый с "+" в LOGIN. Нормализовал через тот же общесайтовый `deFormatPhone()` (include/authHandlers.php), которым уже пользуется заказ в 1 клик — теперь везде единый формат "7XXXXXXXXXX".
- **CLI-запуск feed-скриптов всё ещё блокировался гейтом техработ** (~10 мин). "php feed_search.php" в CLI не имеет `$_SERVER["REQUEST_URI"]` вообще (это чисто веб-переменная), поэтому прошлый фикс (сверка по REQUEST_URI) не срабатывал даже для явно разрешённых feed_*.php — переменная была пустой, ни одно условие не совпадало, гейт блокировал сам себя. Добавлена проверка `PHP_SAPI !== 'cli'` — весь гейт (не файл целиком, остальной init.php для CLI по-прежнему нужен) пропускается для консольных запусков: там нет публичного посетителя, гейт для него не имеет смысла.

## 2026-09-29

- **/catalog/find_by_code.php редирект теперь на фронте** (~40 мин). Раньше эта ссылка (QR-коды/ценники, ?code=<артикул>) жила на back.topdisc.ru как PHP-скрипт, искала товар по CML2_ARTICLE и 301-редиректила на страницу товара, но back.topdisc.ru больше не отдаёт публичный HTML вообще — только API. Перенёс редирект в server.js (перехват до React Router/SSR, как и trailing-slash редирект для товаров): резолвит артикул через новый REST-метод app_mobile.findProductByArticle (api_metods.php, ищет по PROPERTY_CML2_ARTICLE в обычном и премиум-инфоблоках, возвращает section_code+product_code), 301 на /catalog/:categoryCode/:productCode с сохранением остальных query-параметров (utm_source и т.п.), при ненайденном товаре/ошибке — на /catalog/. Проверено локально сборкой и запуском server.js — маршрут перехватывается верно, fallback работает; сам поиск по артикулу непроверяем без деплоя api_metods.php на бэкенд.
- **findProductByArticle всегда открывал один и тот же товар из премиум-инфоблока** (~15 мин). Причина: Bitrix `GetList()` молча игнорирует фильтр по `PROPERTY_XXX`, если такого свойства нет на конкретном инфоблоке (не ошибка — условие просто выпадает). На премиум-инфоблоке свойство `CML2_ARTICLE`, похоже, не заведено — фильтр отваливался, и `nTopCount=1` возвращал первый попавшийся элемент независимо от запрошенного артикула. Исправлено: теперь сверяется реальное значение `PROPERTY_CML2_ARTICLE_VALUE` найденного элемента с искомым кодом, а не сам факт «что-то нашлось». Стоит также проверить в админке Bitrix, есть ли у премиум-инфоблока вообще свойство CML2_ARTICLE — если нет, поиск по артикулу для премиум-товаров технически невозможен, пока его не заведут.
